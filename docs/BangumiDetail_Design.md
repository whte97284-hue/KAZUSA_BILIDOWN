# BiliCommander · 番剧详细下载区（PageBangumi）设计书

> 版本：v1.0 ｜ 日期：2026-08-20 ｜ 目标实现端：QML + C++17（Qt6）
> 设计原则：极简、文字降噪、色彩统一（中性深灰主题）、扁平、无字流派

---

## 1. 背景与目标

当前应用解析后直接"加入待下载列表"，多 P / 番剧集数没有可视化选择与批量入队的入口。本设计新增一个**详细下载区**（独立导航页面），提供类似 B 站番剧详情页的观感：左侧番剧信息 + 右侧分 P 列表 + 底部下载设置条，支持整季/选集批量入队。

**明确边界（重要）**：数据源**始终是哔哩哔哩官方接口**（普通视频 `x/web-interface/view`、番剧 `pgc/view/web/season`），**绝不调用任何第三方站（含 bangumi.tv）**。"番剧详情观感"仅指布局美学参考，不是数据来源。

---

## 2. 导航结构调整

现状（`main.qml` `StackLayout`）：

| index | 现页面 | 调整后 |
|---|---|---|
| 0 | PageDownload（快速下载，首页） | **保持** · 快速下载：输入即下，单 P 直接入队 |
| 1 | PageBatch（占位说明卡） | **替换为 PageBangumi · 详细下载区** |
| 2 | PageHistory | 保持 |
| 3 | PageSettings | 保持 |

要点：

- `main.qml` 中 `PageBatch {}` → `PageBangumi {}`；`FluNavigationView` 第 2 个导航项文案由"批量"改为"详细下载"
- 原"批量多行解析"能力**保留在快速下载页的批量弹窗**（`PageDownload.qml` 已有），不新建
- 解析到**多 P / 番剧**时自动切到 `pageStack.currentIndex = 1`（由 QML 端 `pageCount > 1 || isBangumi` 判断），单 P 普通视频停留首页直接入队

## 3. 页面布局（v2 极简版）

整体为**垂直三段**：顶栏 / 内容区（左右分栏）/ 底部设置条，间距用统一 token（`spacer-16`）。

```
┌────────────────────────────────────────────────┐
│  ‹  动画标题（单行截断，粗体）                    │   ← 顶栏：返回 + 标题，无多余按钮
├────────────────────────────────────────────────┤
│  [16:9 封面 220px]    [全24话][日本][2026]       │   ← 信息区：左封面，右胶囊+评分
│                     9.2 · hover封面看简介        │
│  ───────────────────────────────────────────── │
│  已选 5 / 24                        [全选]       │   ← 列表头
│  ┌──────────────────────────────────────────┐  │
│  │ 01  第1话 标题标题标题           24:00    │  │   ← 分P列表（多选）
│  │ 02  第2话 标题                   24:00    │  │
│  │ 03 ●第3话 标题（选中态）          24:00    │  │
│  └──────────────────────────────────────────┘  │
├────────────────────────────────────────────────┤
│  [清晰度▾] [编码▾] [保存到▾]           [入队]   │   ← 底部设置条（1px上边框）
└────────────────────────────────────────────────┘
```

### 3.1 顶栏

- 左：返回箭头（IconOnly 圆钮）
- 右：大标题（`fontTitle` 粗体，单行截断 elide）
- **不放任何操作按钮**

### 3.2 信息区（左右分栏，非对称留白）

- 左：封面 `Image` 16:9、宽 220px、`radius-card`，`source = currentCover`
- 右：
  - 胶囊行（≤3 个，多的丢弃）：`全 N 话`（brand 强调）、地区、年份
  - 评分：大数字 `9.2`（mono 粗体）+ 星点，**不写"评分"二字**
  - 简介：**默认不显示**，hover 封面浮出（见 §4 防溢出约束）

### 3.3 分 P 列表

- 列表头：左 `已选 N / 总集数`（纯数字），右 `全选`（胶囊 ghost）
- 行：`序号（mono）| Part标题 | 时长`，行高紧凑、hover 高亮 `surfaceHover`、选中 `surfaceActive` + 左缘 6px 语义圆点
- 多选：单击行切换选中，Shift 连选；`ListView` 滚动，几十集不卡

### 3.4 底部下载设置条（解决"设置没地方放"）

- 1px 上边框与内容区隔开
- 左：三个下拉胶囊 `清晰度 ▾` `编码 ▾` `保存到 ▾`（默认值读 `defaultQuality` / `defaultCodec` / `downloadDir`，用户改过即记住）
- 右：唯一主按钮 `入队`（brand 填充胶囊）
- **全页操作收敛为这一个主按钮**

## 4. 关键约束 ①：简介超长防溢出

> 目标：简介再长也**绝不挤压页面高度、绝不撑破布局**。

- 简介**永不 inline 展开**，一律走悬浮卡片（`QtQuick.Controls.Popup`，`Overlay` 承托）
- 浮层属性：`maxHeight` 固定（如 240px）；内部 `Text` 自动换行 + `clip`；超出部分用 `Flickable`/`ScrollView` 滚动
- `Popup` 默认不参与父布局，天然不挤压高度
- 边界兜底：浮层靠近窗口边缘时由 Qt Popup 定位策略自动翻转，不溢出窗口可视区
- 展示动效：fade + 轻微上移 ≤150ms

---

## 5. 关键约束 ②：解析缓存

> 目标：快速下载与详细下载区两入口解析同一番剧，**不重复打接口、不触发风控**。

现有基础：`BiliController` 持有 `m_currentDetail` 且有"10 分钟内复用"逻辑。本设计**升级为多键缓存**：

- 缓存结构：`std::unordered_map<std::string, { BiliVideoDetail detail; int64_t timestamp; }>`
- key：归一化输入标识（`bvid` / `ep_id` / `season_id`，去掉前缀歧义）
- TTL：**10 分钟**；命中且未过期 → 直接复用，不重新发起 Wbi / 详情请求
- 覆盖范围：
  - 快速下载页解析 → 写入缓存
  - 详细下载区展示 → 读缓存
  - 入队取流 → 取流 URL 有效期内复用（120 分钟），过期**仅重新取流、不重新解析详情**
- 生命周期：缓存挂在 `BiliController` 上，**页面切换/销毁不丢缓存**
- 手动刷新：详情页提供刷新入口（可选小按钮）→ 清除该 key 缓存并强制重新解析

## 6. C++ 侧接口变更清单

### 6.1 已有（可直接复用）

`currentTitle / currentCover / currentOwner / currentDuration / isBangumi / pageCount / selectedPageIndex / pageModel`（role：`pageNumber / cid / title / durationDesc / firstFrame`）/ `trackModel`

### 6.2 需新增暴露（Q_PROPERTY，`videoDetailChanged` 通知）

| 属性 | 类型 | 来源 |
|---|---|---|
| `currentDesc` | QString | 番剧 season 接口 `evaluate`/简介 |
| `currentScore` | double | season 接口评分 |
| `currentSeasonInfo` | QString | 组合串：地区/年份/状态(连载/完结)/总集数 |
| `currentViews` | QString | 播放量（格式化） |

### 6.3 需新增方法（Q_INVOKABLE）

| 方法 | 说明 |
|---|---|
| `enqueueAllPages()` | 全部 P 批量入队（每 P 一个 DownloadTask，带 `pageIndex`） |
| `enqueuePages(QVariantList indices)` | 按选中索引批量入队 |
| `refreshDetail()` | 清当前 key 缓存并重新解析 |

### 6.4 其他

- 解析缓存 map + TTL 实现（`BiliController` 内）
- 批量入队时**解析/取流走现有串行队列**，禁止并发打 playurl，防风控

## 7. 交互流

```
快速下载页：粘贴 BV/番剧URL → 解析
   ├─ 单P 普通视频 → 直接入队，停留首页
   └─ 多P / 番剧  → 自动切到「详细下载区」
详细下载区：
   展示 封面/标题/胶囊/评分 + 分P列表
   → 选P（单选/多选/全选）
   → 底部设置条：清晰度 / 编码 / 保存路径
   → 点「入队」→ 通知「已加入 N 个任务」
   → 用户切回快速下载页查看队列进度
```

## 10. 验收标准

1. 番剧 URL / 多 P BV 解析 → 自动进入详细下载区，封面/标题/胶囊/评分/分 P 列表正确
2. 简介超长：悬浮卡片内滚动，**主页面高度不被挤压**
3. 快速与详情两入口解析同一番剧 → 缓存命中，不重复发请求（日志验证）
4. 全选/多选/批量入队 → 生成正确数量任务，`pageIndex` 正确，产物按 P 命名
5. 底部设置条清晰度/编码/路径生效，且记住用户改动
6. 深浅色模式表现均正常，无硬编码色值
7. 下载过程无并发打接口导致的风控 412
